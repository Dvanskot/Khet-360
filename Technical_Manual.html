Technical Installation Manual

The Khet-360 ERP is a layered multi-tenant system. This manual provides the sequence for deploying the Platform Control Plane and the Tenant Business Plane.

System Architecture

Khet-360 employs a strict isolation model to ensure data security and regulatory compliance.

Architectural Note The system is split into two planes:
  • Platform Control Plane: A shared database managing tenant registration, subscription entitlements, and global lookups (e.g., Positions, Leave Types).
  • Tenant Business Plane: A dedicated, isolated SQL Server database per tenant containing all business truth.

Prerequisites

Ensure the following tools are installed on the host machine before proceeding:

.NET 8 SDK
Core runtime for the Backend API.
Docker Desktop
For SQL Server, Redis, RabbitMQ, and MinIO containers.
Node.js & NPM
Runtime for the Vue 3 Frontend.
Git
Version control for codebase management.

Infrastructure Setup

The infrastructure layer provides the required stateful services using Docker Compose.

1
Start Docker Desktop

Ensure the Docker daemon is running and accessible via the CLI.

2
Deploy Containers 
docker compose up -d

This initializes the following services:

  • SQL Server : Port 1433
  • Redis : Port 6379
  • RabbitMQ : Port 5672 (UI: 15672)
  • MinIO : Port 9000 (UI: 9001)

Backend Configuration

The .NET 8 API handles the orchestration of both the Platform and Tenant planes.

1
Navigate to API 
cd src/Khet360.Api
2
Run the Application 
dotnet run

The API will start on http://localhost:5226 by default.

Database Initialization The first run will automatically seed the Platform Database with essential global data (Tax Brackets, Positions, and Leave Types).

Frontend Setup

The user interface is a Vue 3 Single Page Application (SPA) using the Composition API.

1
Install Dependencies 
cd frontend
npm install
2
Launch Development Server 
npm run dev

The frontend will typically be available at http://localhost:5173.

Environment Variables

Configure the .env file in the root directory to manage secrets and connection strings.

MSSQL_SA_PASSWORD
Root password for the SQL Server instance.
REDIS_PASSWORD
Authentication key for the Redis cache.
RABBITMQ_DEFAULT_USER
Admin username for RabbitMQ.
MINIO_ROOT_USER
Admin credentials for S3 Object Storage.
Jwt:PlatformKey
Secret key for Platform-level JWT signing.
Jwt:TenantKey
Secret key for Tenant-level JWT signing.

Smoke Testing

Perform these checks to ensure the system is correctly configured.

1
API Health Check

Navigate to http://localhost:5226/swagger. You should see the Swagger UI documenting all available endpoints.

2
Infrastructure Check

Access the MinIO console at http://localhost:9001 and RabbitMQ management at http://localhost:15672 using the credentials defined in your .env.

Critical Warning Never commit your .env file to version control. Always use a .env.example template for new developers.
